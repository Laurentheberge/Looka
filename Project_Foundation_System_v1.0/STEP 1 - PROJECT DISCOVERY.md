# PROJECT FOUNDATION SYSTEM

## STEP 1: PROJECT DISCOVERY
### Turn the Idea Into a Clear Project Brief

You are helping me turn an initial idea into a clear software project definition.

Do not start coding.

Your job in this step is to remove ambiguity and collect the information needed to
understand what should be built.

Ask questions where important information is missing. Do not invent requirements.

## 1. PROJECT IDENTITY

Ask for:

- Project name
- One sentence description
- What the project does
- Why it exists
- Current stage
- Whether it is a website, web app, PWA, mobile app, desktop app, or another product

## 2. PROBLEM

Identify:

- What problem does this solve?
- Who experiences the problem?
- How are they solving it today?
- Why are existing solutions insufficient?
- What happens if this problem is not solved?

## 3. TARGET USERS

Identify:

- Primary users
- Secondary users
- User experience level
- Devices they are likely to use
- Important location or market considerations
- What users are trying to accomplish

## 4. CORE VALUE

Ask:

- What is the main promise of the product?
- What is the single most important action users should be able to complete?
- What makes this product useful?
- What makes it different from alternatives?

## 5. MVP

Identify:

- Must-have features
- Nice-to-have features
- Features explicitly excluded from the MVP
- What a successful first version looks like

Do not allow the MVP to become unnecessarily large.

## 6. BUSINESS MODEL

Where applicable, identify:

- Free or paid
- Subscription
- One-time payment
- Commission
- Advertising
- Freemium
- Other revenue model

Do not invent a monetization strategy if one has not been decided.

## 7. PROJECT CONSTRAINTS

Ask about:

- Budget
- Timeline
- Existing technology
- Existing code
- Existing database
- Existing domain
- Hosting preferences
- Third-party services
- Team size
- AI coding tools
- Technical limitations

## 8. BRAND AND DESIGN

Collect:

- Brand name
- Brand personality
- Preferred visual direction
- Colors
- Typography preferences
- Light/dark mode
- Reference products
- Design restrictions

Do not choose a visual identity without enough information.

## 9. IMPORTANT REQUIREMENTS

Identify:

- Authentication
- User roles
- Payments
- Notifications
- File uploads
- Search
- Analytics
- Integrations
- Admin functionality
- Data privacy
- Other important requirements

## 10. QUESTIONS GAP ANALYSIS

After collecting the information, identify:

### KNOWN
What is clearly defined.

### UNKNOWN
What is missing.

### ASSUMED
Anything that would otherwise require an assumption.

### CONFLICTS
Requirements that contradict one another.

Do not silently resolve important conflicts.

## 11. CREATE THE PROJECT BRIEF

Create:

`docs/PROJECT_BRIEF.md`

Include:

- Project overview
- Problem
- Target users
- Core value proposition
- MVP scope
- Business model
- Constraints
- Brand/design direction
- Important requirements
- Known decisions
- Open questions
- Assumptions

## 12. FINAL OUTPUT

Before finishing Step 1, show:

1. Project summary
2. Target users
3. Problem
4. Core solution
5. MVP scope
6. Constraints
7. Known decisions
8. Open questions
9. Assumptions
10. Recommended next step

Do not build the application yet.
