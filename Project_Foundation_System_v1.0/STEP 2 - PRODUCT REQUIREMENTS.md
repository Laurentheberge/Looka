# PROJECT FOUNDATION SYSTEM

## STEP 2: PRODUCT REQUIREMENTS
### Turn the Project Brief Into a Buildable Product Specification

Read:

`docs/PROJECT_BRIEF.md`

Do not start coding.

Your job is to convert the project idea into a detailed product specification that an AI
developer can implement without guessing.

## 1. PRODUCT GOAL

Define:

- Product goal
- Primary user outcome
- Business objective
- MVP success criteria

## 2. USERS AND ROLES

For each user type define:

- Who they are
- What they can see
- What they can create
- What they can edit
- What they can delete
- What they cannot access

## 3. USER JOURNEYS

Map the important journeys from beginning to end.

Example:

Sign up
-> onboarding
-> dashboard
-> core action
-> success

Include alternative and failure paths where relevant.

## 4. INFORMATION ARCHITECTURE

Define:

- Main pages
- Routes
- Navigation
- Public pages
- Protected pages
- Admin areas
- Settings
- Important screens

## 5. FEATURES

For each feature define:

### Feature
Name

### Purpose
Why it exists

### User
Who uses it

### Behavior
What happens

### Inputs
What the user provides

### Outputs
What the system returns

### Rules
Important business logic

### Permissions
Who can use it

### States
Loading, empty, success, error, disabled, and other relevant states

### Acceptance Criteria
What must be true for the feature to be considered complete

## 6. MVP BOUNDARY

Separate:

### MVP
What must be built now.

### POST-MVP
What can wait.

### EXCLUDED
What should not be built unless explicitly added later.

Do not allow scope creep.

## 7. DATA REQUIREMENTS

Identify what information the product needs to store.

Do not design the database yet.

Document:

- Data entities
- Ownership
- Relationships
- Important fields
- Data lifecycle
- Retention requirements where relevant

## 8. AUTHENTICATION AND AUTHORIZATION

Define:

- Sign up
- Sign in
- Sign out
- Password reset
- Verification
- OAuth where applicable
- User roles
- Permissions
- Protected areas

## 9. INTEGRATIONS

Document required external services.

For each one include:

- Purpose
- What data is exchanged
- When it is used
- Failure behavior
- Whether it is required for MVP

## 10. BUSINESS LOGIC

Write important rules explicitly.

Examples:

- Who can perform an action
- When something becomes available
- What happens after payment
- What happens when a record is deleted
- Limits
- Status changes
- Subscription rules

Do not leave important logic implied.

## 11. UX STATES

For each major workflow define:

- Loading
- Empty
- Success
- Error
- Disabled
- Unauthorized
- Not found

Only include states that apply.

## 12. NON-FUNCTIONAL REQUIREMENTS

Define relevant expectations for:

- Security
- Performance
- Accessibility
- Responsiveness
- Reliability
- Privacy
- Scalability

Do not invent unrealistic requirements.

## 13. ACCEPTANCE CRITERIA

Create acceptance criteria for every MVP feature.

Criteria should be specific enough for an AI developer to verify.

## 14. CREATE THE PRD

Create:

`docs/PRD.md`

Include all finalized requirements and clearly separate open questions from confirmed
requirements.

## 15. FINAL GAP CHECK

Identify:

- Missing requirements
- Conflicting requirements
- Unclear business rules
- Missing user journeys
- Missing permissions
- Missing error states
- Missing integrations
- Scope risks

Ask only the questions necessary to resolve important gaps.

## 16. FINAL OUTPUT

Provide:

1. Product goal
2. Users and roles
3. User journeys
4. Information architecture
5. MVP features
6. Business rules
7. Data requirements
8. Authentication and permissions
9. Integrations
10. Acceptance criteria
11. Open questions
12. Scope risks

Do not start implementation.
